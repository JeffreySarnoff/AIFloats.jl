Projections

A format holds finitely many values, so most reals are not among them. A projection is the choice of how a real is mapped onto one that is: a rounding mode for values that fall between neighbours, and a saturation mode for values past the largest.

Use a projection with Convert, a registered operation, or project. Projection is the package's single code-point write path, so the selected rounding and saturation behavior is applied exactly once.

Rounding modes

Nine modes, each a singleton with a short name and a long one:

ConstantLong nameFamilyBehavior
RTERoundToEvento nearestnearest; ties to the even last bit
RTARoundToAwayto nearestnearest; ties away from zero
RTPRoundTowardPositiveunidirectionaltoward +Inf
RTNRoundTowardNegativeunidirectionaltoward −Inf
RTZRoundTowardZerounidirectionaltruncate
RTORoundToOddparityinexact results get a 1 last bit
RSAStochasticAstochasticrandomized
RSBStochasticBstochasticrandomized
RSCStochasticCstochasticrandomized

The families are types, so a group can be dispatched on or tested as a group:

julia> RTE isa AIFloats.ToNearestRoundingMode
true

julia> RTZ isa AIFloats.DeterministicRoundingMode
true

julia> RSA isa AIFloats.StochasticRoundingMode
true

AIFloats.DeterministicRoundingMode covers the to-nearest, unidirectional, and parity families — everything except the stochastic three.

Why three kinds matter at low precision

RTE is the familiar default and is unbiased, which is why IEEE 754 chose it.

RTO is also unbiased and much cheaper in hardware, at roughly twice the rounding error. Its real use is avoiding double rounding: round a wide intermediate to odd, then narrow it, and the second rounding lands where a single direct rounding would have.

Stochastic rounding rounds up or down at random, so it is unbiased in expectation rather than per-operation. That matters when a weight update is smaller than one unit in the last place: deterministic rounding discards every such update, while stochastic rounding lets them accumulate. It is the reason very low-precision training works at all.

Saturation modes

Three modes, covering what happens to a value too large for the format:

ConstantLong nameFamily
SFSatFinitesaturating
SPSatPropagatesaturating
SNSatNonenon-saturating
julia> SF isa AIFloats.SaturatingSaturationMode
true

julia> SN isa AIFloats.NonsaturatingSaturationMode
true

Short and long names

Every mode answers to both. Lowercase string gives the short name, capital String the long one:

julia> string(RTE), String(RTE)
("RTE", "RoundToEven")

julia> string(SF), String(SF)
("SF", "SatFinite")

Displaying a mode uses the short name:

julia> RTE
RTE

Pairing them

A Projection is one rounding mode and one saturation mode together:

julia> p = Projection(RTA, SN)
ρ(RTA, SN)

julia> RoundOf(p), SatOf(p)
(RTA, SN)

All 27 pairings exist as constants named <rounding>_<saturation>, so building one is usually unnecessary:

julia> p === RTA_SN
true

The full set runs RTE_SF, RTE_SP, RTE_SN, RTA_SF, … , RSC_SN. RTE_SF — round to nearest, ties to even, saturating — is the conventional default.

How projections display

A Projection prints as ρ(rounding, saturation), and like the modes it has a short form and a long one. The short form is what the REPL shows:

julia> RTE_SF
ρ(RTE, SF)

julia> repr(RTE_SF)
"ρ(RoundToEven, SatFinite)"

Technical examples

These examples are useful when integrating AIFloats into a numerical library, investigating performance, or checking conformance assumptions.

Inspect carrier selection

The format's exponent span determines its internal carrier rung independently of its storage width.

using AIFloats

formats = (
    Binary(8, 4, SIGNED, EXTENDED),
    Binary(16, 4, SIGNED, EXTENDED),
    Binary(16, 1, UNSIGNED, FINITE),
)

[(F, AIFloats.rung(F), AIFloats.datumcarrier(F)) for F in formats]
3-element Vector{Tuple{DataType, AIFloats.Head, DataType}}:
 (Binary{8, 4, SIGNED, EXTENDED}, AIFloats.HeadF64(), Float64)
 (Binary{16, 4, SIGNED, EXTENDED}, AIFloats.HeadF128(), Quadmath.Float128)
 (Binary{16, 1, UNSIGNED, FINITE}, AIFloats.HeadExact(), AIFloats.DyadicNumbers.Dyadic)

Carrier types are implementation details and are not part of the stable interface. Use decode, registered operations, and project rather than depending on a particular rung.

Inspect table policy without building a table

using AIFloats

F8 = BinaryFormatOf(Binary8p4se)
F9 = Binary(9, 4, SIGNED, EXTENDED)

eager = AIFloats.table_policy(:Add, F8, F8, F8, RTE_SN)
adaptive = AIFloats.table_policy(:Add, F9, F9, F9, RTE_SN; nelems=65_536)
(eager, adaptive)
((shape = :A, entries = 65536, bytes = 65536, state = :eager, cumulative = 0, threshold = 0, reason = "eager build band"), (shape = :B, entries = 262144, bytes = 524288, state = :adaptive_pending, cumulative = 0, threshold = 1000000, reason = "adaptive table needs 1000000 more cumulative elements"))

The returned state explains the decision. shape = :A means the matching kernel call is eligible to fetch/build a table and gather from it; shape = :B means it will compute each element through the scalar operation.

stateMeaning
:eagerThe operand-code bits fit the eager build band. The next call may fetch an existing table or build it immediately, regardless of array length.
:adaptive_pendingThe signature fits the adaptive band but is not cached and has not processed enough cumulative elements to pay for a build. The call computes scalarly.
:adaptive_earnedThe cached use count plus the supplied prospective nelems reaches the build threshold. A real call of that size would build and then use the table. Calling table_policy itself does not build it or change the count.
:adaptive_cachedAn adaptively earned table has already been built and is available for a gather.
:stochasticStochastic projection depends on a random draw, so it is never represented by one deterministic result table.
:over_byte_budgetThe complete table would exceed the configured per-table memory ceiling.
:over_adaptive_bandThe operand-code space is beyond the largest band for which policy permits a table build.

cumulative is the number of elements previously seen for that adaptive signature, and threshold is the count required to earn its table. Supplying nelems asks what a future call of that size would do without incrementing cumulative or changing the cache.

Inspect the table cache

AIFloats.table_stats() is one locked snapshot: its counts and its byte total describe the same moment, which is why it exists rather than a pair of separate queries.

using AIFloats

s = AIFloats.table_stats()
(s.entries, s.bytes, s.by_arity)
(4, 131360, (unary = 2, binary = 2, ternary = 0))

AIFloats.table_entries() is a second locked snapshot, per entry, naming format types and the mode names you write. Populate the cache through the ordinary array path — vmap — rather than reaching for a private builder:

using AIFloats

AIFloats.empty_tables!()

F = Binary(3, 2, SIGNED, FINITE)          # ΣK = 3: comfortably in the eager band
T = BinaryValue(F)
A = T[0.5, 1.0, 1.5]
vmap(:Negate, F, RTE_SN, A)               # this is what builds and caches the table

entries = AIFloats.table_entries()
[(e.op, e.result, e.operands, e.rounding, e.saturation, e.bytes) for e in entries]
1-element Vector{Tuple{Symbol, DataType, Tuple{DataType}, Symbol, Symbol, Int64}}:
 (:Negate, Binary{3, 2, SIGNED, FINITE}, (Binary{3, 2, SIGNED, FINITE},), :RTE, :SN, 8)
Two snapshots are two moments

Each of table_stats() and table_entries() is internally coherent, but they are separate calls. The entry bytes sum to a separately obtained table_stats().bytes only if the cache is not mutated between them — another task's first array call is enough to break it.

Where one coherent count-and-byte declaration is required, use conformance: it derives its byte total from the very entry vector it captured.

using AIFloats

c = conformance()
(length(c.cached_specializations), c.cached_bytes)
(1, 8)

Compare the fast enclosure with the rigorous ladder

The performance switch is intended for differential testing. Both paths must produce the same final code point:

using AIFloats

T = Binary8p4se
x = T(1.5)
fast = Exp(T, RTE_SN, x)

saved = AIFloats.FAST_ENCLOSURE[]
rigorous = try
    AIFloats.FAST_ENCLOSURE[] = false
    Exp(T, RTE_SN, x)
finally
    AIFloats.FAST_ENCLOSURE[] = saved
end

(fast, rigorous, codepoint(fast) == codepoint(rigorous))
(4.5, 4.5, true)

This switch is diagnostic, not a request for weaker rounding. The fallback is the correctly rounded MPFR enclosure ladder. In particular, no Quadmath transcendental result is assumed to be correctly rounded.

Examine raw codes and the total order

using AIFloats

T = BinaryValue(Binary8p4se)
samples = T[fromcode(T, c) for c in (0x00, 0x01, 0x40, 0x7f, 0x80, 0xff)]
[(codepoint(x), decode(x), Class(x), AIFloats.order_key(x)) for x in samples]
6-element Vector{Tuple{UInt8, Float64, FPClass, UInt16}}:
 (0x00, 0.0, ClassZero, 0x0081)
 (0x01, 0.0009765625, ClassPosSubnormal, 0x0082)
 (0x40, 1.0, ClassPosNormal, 0x00c1)
 (0x7f, Inf, ClassPosInf, 0x0100)
 (0x80, NaN, ClassNaN, 0x0000)
 (0xff, -Inf, ClassNegInf, 0x0001)

Sorting uses the draft's NaN-first total order:

using AIFloats

T = BinaryValue(Binary8p4se)
samples = T[fromcode(T, c) for c in (0x00, 0x01, 0x40, 0x7f, 0x80, 0xff)]
sort(samples)
6-element Vector{BinaryValue(Binary8p4se)}:
 NaN
 -Inf
   0.0
   0.0009765625
   1.0
  Inf

Query the conformance declaration

using AIFloats

c = conformance()
(draft_revision(), draft_identity(), typeof(c))
("IEEE P3109 Interim Report on Arithmetic Formats for Machine Learning, version 4.0.3 (2026-09-01) — unapproved draft; not for conformance/compliance use", (designation = "IEEE P3109 Interim Report on Arithmetic Formats for Machine Learning", report_revision = "4.0.3", report_date = "2026-09-01", report_url = "https://github.com/P3109/Public/blob/main/IEEE%20P3109%20Interim%20Report.pdf", report_sha256 = "7de115ed6882b7550b8fa61e81e5173857b340c3bfe30db8d4ad74b472229b9e", report_status = "unapproved draft; not for conformance/compliance use", retained_designation = "IEEE P3109/D1", retained_uploaded = "2026-07-17", retained_source = "docs/other/IEEE_D1.md", transliteration_sha256 = "820cb5009cd6fe9032f5bdfb661bc639e33296f716a552eafc81f899411bb5f2"), AIFloats.ConformanceDeclaration)

Use conformance_report for the human-readable declaration and conformance_dict for structured tooling.

draft_identity() names the designated Interim Report — revision, date, URL, and the SHA-256 of the PDF the implementation was compared against — alongside the retained transliteration it was originally written from. The report is an unapproved draft; its cover states it must not be used for conformance or compliance purposes. conformance() reports what this package implements, in the shape §4.6 describes. It is not IEEE approval, not a certification, and not a compliance determination.

Discover the operation register

The registry is queryable without touching its private storage:

using AIFloats

ops = AIFloats.operations()
by_arity = Dict(a => count(o -> o.arity == a, ops) for a in 1:3)
(total = length(ops), by_arity = by_arity, add = AIFloats.operationinfo(:Add))
(total = 52, by_arity = Dict(2 => 18, 3 => 3, 1 => 31), add = (name = :Add, arity = 2, group = :A, factors = 1))

AIFloats.operations() and AIFloats.operationinfo are the supported entry points; OP_REGISTRY itself is private and its shape is not part of the interface. See Operations.
